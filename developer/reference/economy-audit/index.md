# 经济审查工作流

任何触及货币、商店定价、任务奖励或服务收费的改动，上线前都要跑一遍这五个阶段。

## 何时跑

| 改动类型 | 跑法 |
| :--- | :--- |
| 改一个价格 | 阶段二、阶段三快查 |
| 新功能、新商店 | 五阶段全跑，输出完整报告 |
| 季度性全服经济体检 | 五阶段加数据库实际数据核对 |

审查时对照的基准数值见 [经济基准参考](/developer/reference/economy)。

## 五个阶段

| 阶段 | 目的 | 产出 |
| :--- | :--- | :--- |
| 一、数据采集 | 拿到真实的当前数值 | 采集表 |
| 二、基准对照 | 判断数值是否落在锚点区间 | 占比结论 |
| 三、问题识别 | 逐项跑检查清单 | 问题标记 |
| 四、影响分析 | 推演总量、交叉验证 | 推演结果 |
| 五、报告输出 | 结构化交付 | 审查报告 |

## 阶段一：数据采集

读配置、数据库与源码，逐字核对，不凭记忆。

### 数据源

| 数据源 | 位置 | 说明 |
| :--- | :--- | :--- |
| 插件配置 | `/mnt/miragedge/MainServer/plugins/<插件>/` | 经济数值主来源 |
| 服务器数据库 | MySQL `miragedge.data.top` | 玩家实际余额与流通量 |
| 插件源码 | `F:\Java_project\<插件>\` | 硬编码成本与公式 |
| 任务配置 | MiragEdgeMenu `quest/quests/` | 任务奖励 |
| 商店配置 | UltimateShop `shops/` | 商店价格与限量 |
| 文档站基准 | `developer/reference/economy.md` | 官方锚点 |

### 采集命令

```bash
# 1) 列出插件所有配置文件
ls /mnt/miragedge/MainServer/plugins/<插件>/

# 2) 全文读取（必要时分段）
cat /mnt/miragedge/MainServer/plugins/<插件>/config.yml

# 3) 搜索经济关键词（万能定位）
grep -rn -iE "price|cost|reward|amount|vault|points|灵叶|星痕|fee|limit" \
    /mnt/miragedge/MainServer/plugins/<插件>/

# 4) 数据库实际流通量（核对膨胀）
mysql -h miragedge.data.top -u <user> -p<pass> <db> \
    -e "SELECT SUM(balance) FROM <table>; SELECT COUNT(*) FROM <table>;"
```

### 采集表

| 字段 | 说明 | 示例 |
| :--- | :--- | :--- |
| 插件名 | 所属插件 | LiteSignIn |
| 功能 | 触发入口 | 每日签到 |
| 货币 | vault / points / 其他 | points + vault |
| 数值 | 每次给多少 | 35 星痕石 + 800 灵叶 |
| 频率 | 多久一次 | 每日一次 |
| 限量 | 是否有上限 | 无 |
| 肝度 | 达成成本 | 登录即得 |
| 上下文 | 掉落与获取方式 | 无 |

### 肝度分级

| 肝度 | 说明 | 典型示例 |
| :--- | :--- | :--- |
| 1 级 | 登录或挂机即得 | 签到、在线奖励 |
| 2 级 | 随手可做 | 杀怪、普通挖矿 |
| 3 级 | 需专门刷 | 特定怪物、下界探索 |
| 4 级 | 高难 | Boss、末地城、远古城市 |
| 5 级 | 几乎不可重复 | 龙首、稀有唱片 |

## 阶段二：基准对照

### 货币选择

| 判定条件 | 应使用 |
| :--- | :--- |
| 日常消耗品与服务（传送、死亡、基础材料） | 灵叶 |
| 高级或稀缺功能（高品质附魔、重铸、珍材） | 星痕石 |
| 建筑方块买卖 | 块币（灵叶兜底） |
| 限量或稀有收藏品（龙首、唱片） | 星痕石 |
| 可再生装饰品（草、花、菌） | 灵叶，不移入星痕石商店 |

常见错误：

- 可再生装饰品标价星痕石，占用稀缺货币的位置。
- 日常传送标价星痕石，流通量撑不起日常消费。
- 该用块币的建筑材料标灵叶，冲击基础货币体系。

### 肝度与价值匹配

物品的商店价格与其获取肝度成正比。

| 肝度 | 建议占日收入 | 理由 |
| :--- | :--- | :--- |
| 1 级 | 1~5% | 几乎免费 |
| 2 级 | 5~15% | 随手可做 |
| 3 级 | 15~30% | 专门花时间 |
| 4 级 | 30~60% | 高难度 |
| 5 级 | 60~150% | 极稀有 |

算法：物品价格除以日收入得到占比，与上表对照，偏差超过 50% 记为待查项。

两档货币的定价区间表见 [经济定价方法](/developer/reference/economy-audit/pricing-methods)。

## 阶段三：问题识别

对每个被审查的数值逐项跑 [经济审查检查清单](/developer/reference/economy-audit/checklist) 的 10 项检查。

任何一项触发即标记为潜在问题，进入阶段四分析。

## 阶段四：影响分析与定价验证

从单个数值是否合理，升级到整体经济是否健康。

### 日/周/月总量推演

```text
单次数值: ___ 货币
频率: ___ 次/天
日总量: ___ × ___ = ___ /天
周总量: ___ × 7 = ___ /周
月总量: ___ × 30 = ___ /月

对照日注入量: ___ /天
占比: ___%
结论: 合理 / 偏高 / 严重膨胀
```

| 日总量占日注入比 | 判定 |
| :--- | :--- |
| 小于 5% | 可忽略 |
| 5~20% | 合理范围 |
| 20~50% | 需关注，确认有对应回收 |
| 大于 50% | 严重膨胀风险 |

### 相邻插件交叉验证

1. 搜索全部插件配置，列出同货币的所有消费与产出点。
2. 按价格排序，检查相对合理性。
3. 检查任务奖励是否仍有吸引力，商店价格不应碾压任务奖励。
4. 检查回收渠道是否仍然够用。

```text
示例：珍材商店「经验修补」从 280 调整为 300 星痕石
  祛魔至宝 8 星痕石仍然合理
  月卡日产出 100~150 颗，300 约占 2 天收入
  任务上交委托的星痕石奖励仍有吸引力
```

### 配置项逐项核对

| 检查项 | 方法 |
| :--- | :--- |
| YAML 缩进 | 读源文件确认层级正确 |
| 数据类型 | amount 是字符串还是数字，插件要求哪种 |
| 货币插件名 | `economy-plugin: Vault` 还是 `vault`，大小写敏感 |
| 限量字段 | `buy-limits` 与 `sell-limits` 别搞反 |
| 重置时间 | `TIMED` 与 `00:00:00` 的组合是否正确 |
| 命令引用 | `ferp add xxx -{amount}` 的负号是否在 |
| 权限节点 | `group.vip` 是否与权限插件的实际节点一致 |

## 阶段五：报告输出

按 [经济审查报告模板](/developer/reference/economy-audit/report-template) 填充输出，让决策者一眼看到问题与建议。

全插件经济速查表的数值见 [全插件经济速查表](/developer/reference/economy-audit/plugin-economy-matrix)，基准数据截止 2026-09-02。
