## 一、经济体系全景（基准知识库）

> 本节是审查的**基准参照系**。所有新增/修改的经济数值，都必须能对回到本节中的锚点。
> 基准数据截止：2026-09-02。若经济系统有重大调整，先更新本节再审查。

### 1.1 货币体系

| 货币 | 承载插件 | 定位 | 日注入（活跃玩家） | 主要用途 |
|:----|:-------|:----|:-----------------|:--------|
| **灵叶** | Vault (XConomy) | 基础流通货币 | ~22,000/天 | 日常消耗、交易、服务、传送、商店 |
| **星痕石** | PlayerPoints | 高级稀缺货币 | ~100~150/天 | 高品质附魔、重铸、珍材商店 |
| **块币** | EMC 方块银行 | 建筑独立货币 | 无限（卖建材） | 建筑方块购买；不足自动从灵叶代扣 |
| **经验等级** | 原版 | 成长货币 | 随玩法浮动 | 祛魔、附魔、任务 |
| **飞行时间** | TempFly | 权益货币 | 随任务/月卡 | 鞘翅飞行（分钟级） |

**货币汇率锚：**

- **1 星痕石 ≈ 40~50 灵叶**（任务奖励配比推算，允许 ±20% 浮动）
- 1 块币 ≈ 卖建材时等价于灵叶（vault-fallback 代扣）
- 1 次 TPA = 100 灵叶（基础服务锚）

### 1.2 核心价值锚（定价的一切出发点）

| 锚点 | 数值 | 说明 |
|:----|:----|:----|
| 1 颗钻石（卖） | **1,200 灵叶** | 全服最硬的价值锚 |
| 1 颗钻石（买） | 1,600 灵叶 | 官方供应池价格 |
| 1 天灵叶收入 | ~22,000 灵叶 | 在线10,000 + 任务12,000 |
| 1 天星痕石收入 | ~100~150 颗 | 在线30 + 任务40 + 签到35 + 浮动 |
| 1 天生存开销 | 8,000~26,000 灵叶 | 死亡+传送+祛魔+重铸 |

### 1.3 日平衡表（注入 vs 回收）

#### 灵叶日注入（~22,000）

| 来源 | 灵叶/天 |
|:----|:------:|
| 在线奖励（满8h） | 10,000 |
| 每日任务（做满） | ~12,000 |
| 挖矿/打怪/赏金 | 浮动（3,000~5,000） |

#### 灵叶日回收（14,800~25,800）

| 渠道 | 回收量/天 |
|:----|:-------:|
| 稀有资源商店差价 | ~5,800 |
| 死亡惩罚/返回 | 5,000~10,000 |
| TPA 传送 | 1,000~2,000 |
| 附魔消耗（祛魔/重铸/增幅） | 3,000~8,000 |
| EMC 重构损耗 | ~500 |

**总体状态：基本平衡，略有弹性结余。**

#### 星痕石日注入（~100~150）

| 来源 | 星痕石/天 |
|:----|:-------:|
| 在线奖励 | 30 |
| 每日任务 | 38~43 |
| 签到 | 35（补签30，全服第一70） |
| 周任务折算 | ~41 |
| 知识问答/竞技场/月卡 | 浮动 0~160 |

#### 星痕石日消耗

| 渠道 | 消耗/次 |
|:----|:------:|
| 祛魔（至宝） | 8 |
| 重铸（至宝） | 15 |
| 重铸（传说） | 5 |
| 增幅（高品质） | 1~2 |
| 珍材商店 | 见商店定价 |

### 1.4 核心设计原则（审查时的第一性原理）

1. **灵叶是基础，星痕石是稀缺**：日常消耗用灵叶，高品质/高级服务用星痕石。
2. **总量守恒**：官方商店"卖入→进池、买入→出池"，总量不变，差价回收货币。
3. **不可再生资源做回收锚**：钻石/远古残骸/下界合金/龙蛋等不可再生资源，是官方定价的锚点。
4. **防套利**：任何价格组合都不能让玩家"买入→转卖/交任务"获利。
5. **限量防垄断**：可无限刷取的资源（龙蛋）必须限量，防止个别玩家垄断印钞。
6. **回收 > 注入才不膨胀**：货币总量增长的插件要克制，回收渠道要充足。
7. **玩家有选择**：每笔花费，玩家都应有"自己做"和"花钱买"两条路，价格决定选择。

- **季度性全服经济体检**：全程 + 数据库实际数据核对

## 三、阶段一：数据采集

> 目的：拿到"真实的当前数值"，不凭记忆或猜测。
> 铁则：**读配置/数据库/源码，逐字核对，不脑补。**

### 3.1 数据源清单

| 数据源 | 位置 | 说明 |
|:-----|:----|:----|
| 插件配置 | `/mnt/miragedge/MainServer/plugins/<插件>/` | 经济数值主来源 |
| 服务器数据库 | MySQL `miragedge.data.top` | 玩家实际余额、流通量 |
| 插件源码 | `F:\Java_project\<插件>\` | 硬编码成本/公式 |
| 任务配置 | MiragEdgeMenu `quest/quests/` | 任务奖励 |
| 商店配置 | UltimateShop `shops/` | 商店价格/限量 |
| 文档站基准 | `developer/reference/economy.md` | 官方锚点 |

### 3.2 采集命令模板

```bash
# 1) 列出插件所有配置文件
ls /mnt/miragedge/MainServer/plugins/<插件>/

# 2) 全文读取（必要时分段）
cat /mnt/miragedge/MainServer/plugins/<插件>/config.yml

# 3) 搜索经济关键词（万能定位）
grep -rn -iE "price|cost|reward|amount|vault|points|灵叶|星痕|fee|limit" \
    /mnt/miragedge/MainServer/plugins/<插件>/

# 4) 数据库实际流通量（核对膨胀）
mysql -h miragedge.data.top -u <user> -p<pass> <db> \
    -e "SELECT SUM(balance) FROM <table>; SELECT COUNT(*) FROM <table>;"
```

### 3.3 采集表模板

| 字段 | 说明 | 示例 |
|:----|:----|:----|
| 插件名 | 所属插件 | LiteSignIn |
| 功能 | 触发入口 | 每日签到 |
| 货币 | vault/points/其他 | points + vault |
| 数值 | 每次给多少 | 35 星痕石 + 800 灵叶 |
| 频率 | 多久一次 | 每日一次 |
| 限量 | 是否有上限 | 无 |
| 肝度 | 达成成本 | 登录即得 |
| 上下文 | 掉落/获取方式 | 无 |

### 3.4 肝度分级参考

> 判断价格与肝度是否匹配的标准。

| 肝度 | 说明 | 典型示例 |
|:----|:----|:--------|
| ★☆☆☆☆ | 登录/挂机即得 | 签到、在线奖励 |
| ★★☆☆☆ | 随手可做 | 杀怪、普通挖矿 |
| ★★★☆☆ | 需专门刷 | 特定怪物、下界探索 |

## 四、阶段二：基准对照

> 目的：判断采集到的数值"合不合理"。用基准锚点进行三重对照。

### 4.1 货币选择检查

**规则：问自己——这个功能该用哪种货币？**

| 判定条件 | 应使用 |
|:-------|:------|
| 日常消耗品/服务（传送、死亡、基础材料） | **灵叶** |
| 高级/稀缺功能（高品质附魔、重铸、珍材） | **星痕石** |
| 建筑方块买卖 | **块币**（灵叶 fallback） |
| 限量/稀有收藏品（龙首、唱片） | **星痕石** |
| 可再生装饰品（草、花、菌） | **灵叶或不移入星痕石商店** |

**常见错误：**

- 可再生装饰品标价星痕石（浪费稀缺货币的位置）
- 日常传送标价星痕石（流通量不够日常消费）
- 本应用块币的建筑材料标灵叶（冲击基础货币体系）

### 4.2 日收入占比对照

> **核心公式：该价格占玩家日收入的百分之几？**

#### 灵叶定价区间表

| 占日收入 | 对应灵叶 | 定性 | 适用场景 |
|:------:|:--------|:----|:--------|
| 1~5% | 220~1,100 | 廉价 | 消耗品、基础服务 |
| 5~15% | 1,100~3,300 | 合理 | 常用消耗品 |
| 15~30% | 3,300~6,600 | 中等 | 稀有材料 |
| 30~60% | 6,600~13,200 | 昂贵 | 高级消耗品 |
| 60~100% | 13,200~22,000 | 重度 | Boss材料、顶级附魔 |
| >100% | >22,000 | 奢侈 | 收藏品、终极大件 |

#### 星痕石定价区间表

| 占日收入 | 对应星痕石 | 定性 | 适用场景 |
|:------:|:--------:|:----|:--------|
| 1~10% | 1~15 | 廉价 | 基础消耗 |
| 10~30% | 15~45 | 合理 | 中等消耗 |
| 30~60% | 45~90 | 中等 | 稀有材料 |
| 60~100% | 90~150 | 昂贵 | 高级附魔 |
| >100% | >150 | 奢侈 | 顶级收藏 |

### 4.3 肝度-价值匹配检查

> 一个物品的商店价格，应与其获取肝度成正比。

| 肝度 | 建议占日收入 | 理由 |
|:----|:----------:|:----|
| ★☆☆☆☆ | 1~5% | 几乎免费 |
| ★★☆☆☆ | 5~15% | 随手可做 |
| ★★★☆☆ | 15~30% | 专门花时间 |
| ★★★★☆ | 30~60% | 高难度 |
| ★★★★★ | 60~150% | 极稀有 |

**检查方法：** 将物品价格 ÷ 日收入 = 占比，与上表对照，偏差超 50% 标记为 ⚠️。

## 五、阶段三：问题识别（检查清单）

> 本阶段是整个工作流的核心。对每个被审查的数值，逐项跑以下 10 项检查。
> 任何一项触发即标记为潜在问题，进入阶段四分析。

### 5.1 检查清单（10 项）

#### ① 通胀源检查

**问题：** 该功能是否会持续向系统注入货币而无对应回收？

**检查方法：**

- 该货币来源是否有对应的回收渠道？
- 如果是奖励，玩家"付出"了什么？（时间？物品？技能？）
- 如果只是"登录就给"，是否有每日上限？

**触发条件：** 无上限 + 无回收 → 通胀风险 ⚠️

---

#### ② 回收缺口检查

**问题：** 货币回收渠道是否充足？

**检查方法：**

- 该货币是否有消费渠道（商店、消耗、手续费）？
- 回收量是否 ≥ 注入量的 60%？（否则长期膨胀）
- 回收渠道是否多样化？（单一回收渠道容易被玩家回避）

**触发条件：** 回收/注入 < 60% → 回收缺口 ⚠️

---

#### ③ 套利路径检查

**问题：** 玩家是否能"低价买入→高价卖出"获利？

**检查方法：**

- 从官方商店 A 买入 → 在官方商店 B 卖出 → 是否盈利？
- 从官方商店买入 → 交任务 → 奖励是否 > 买入价？
- 玩家间市场价 vs 官方收购价 → 是否有套利空间？

**检查模板：**

```
路径 1：商店买入 X → 商店卖出 X
  买入价: ___ 灵叶
  卖出价: ___ 灵叶
  差额: ___（应为负值才安全）

路径 2：商店买入 X → 交任务（要求上交 X）
  买入价: ___ 灵叶
  任务奖励: ___ 灵叶 + ___ 星痕石
  净额: ___（应 ≤ 卖商店的价才安全）

路径 3：自己获取 X → 卖商店
  获取成本: 时间/肝度
  卖出价: ___ 灵叶
  结论: ✅ 合理（玩家用时间换钱）
```

**触发条件：** 任一路径净额 > 0 → 套利风险 🔴

---

#### ④ 垄断/刷取检查

**问题：** 该资源是否能被个别人无限刷取？

**检查方法：**

- 该资源可再生吗？（红石农场、刷怪塔、龙蛋循环）
- 如果可再生，是否有每日限量？
- 是否需要高门槛（技能/装备/权限）才能刷？
- 是否需要全服限量（防止一家独大）？

**触发条件：** 可再生 + 无限量 → 垄断风险 ⚠️

---

#### ⑤ 限量缺失检查

**问题：** 需要限量的地方是否有限量？

**检查方法：**

- 列出所有"系统给钱"的渠道（任务、签到、竞技场等）
- 每个渠道是否有每日/每周上限？
- 上限是否合理（不会过低到无聊，也不会高到膨胀）？

**触发条件：** 系统注入渠道无限量 → 🔴

---

#### ⑥ 死循环检查

**问题：** 解锁条件是否依赖该解锁本身提供的能力？

**检查方法：**

- 画出解锁路径：A → B → C
- 检查：B 的解锁条件是否包含 B 本身提供的能力？

**典型反例：** "钓到传说鱼才能解锁传说鱼权限" → 死循环

- 玩家没有传说鱼权限 → 钓不到传说鱼 → 永远无法解锁

**触发条件：** 解锁链中出现循环依赖 → 🔴

---

#### ⑦ 货币混用检查

**问题：** 一个商店/系统中是否混用多种货币，造成混乱？

**检查方法：**

- 该系统所有物品是否用统一货币？
- 如果混用，是否有充分理由？（如：基础品灵叶+精品星痕石）
- 混用时，玩家是否能直观理解换算关系？

**触发条件：** 混用货币且无统一逻辑 → ⚠️

---

#### ⑧ 经验门槛检查

**问题：** 玩家是否有足够的经验等级来消费该功能？

**检查方法：**

- 该功能消耗多少经验等级？
- 玩家一天能获得多少经验？（打怪≈1-3级/h，烧炼≈0.5-1级/h）
- 经验消耗是否在玩家一天能达到的范围内？

**触发条件：** 消耗 > 玩家两天收入的经验 → ⚠️

---

#### ⑨ 付费玩家平衡检查

**问题：** 月卡/付费玩家与免费玩家的货币差距是否过大？

**检查方法：**

- 月卡玩家日收入比免费玩家多多少？
- 差距是否 > 3 倍？（3 倍以上会导致体验割裂）
- 付费产出是否影响星痕石这类稀缺货币的稀缺性？

**当前基准（星痕石月卡）：**

| 档位 | 日额外星痕石 | 占免费日收入比 |
|:----|:----------:|:----------:|
| 新秀 | +28 | +28% |
| 精英 | +55 | +55% |
| 大师 | +110 | +110% |

大师月卡翻倍，需确认是否为设计意图。

**触发条件：** 付费差距 > 3 倍 → ⚠️

---

#### ⑩ 交叉影响检查

**问题：** 该数值变动是否影响其他插件/系统？

**检查方法：**

- 列出所有使用该货币的插件
- 该数值变动后，其他插件的价格是否显得不合理？
- 该数值变动后，是否影响任务奖励的吸引力？

**检查步骤：**

```
1. 搜索所有引用该货币的插件配置
2. 比对价格排序：变动后，相对排序是否合理？
3. 检查任务奖励是否仍然有吸引力（不应被商店价格碾压）
```

**触发条件：** 变动后相对排序不合理 → ⚠️

---

## 六、阶段四：影响分析与定价验证

> 目的：从"单个数值是否合理"升级到"整体经济是否健康"。

### 6.1 日/周/月总量推演

> 把单个数值放入时间维度，看长期趋势。

**推演模板：**

```
单次数值: ___ 货币
频率: ___ 次/天
日总量: ___ × ___ = ___ /天
周总量: ___ × 7 = ___ /周
月总量: ___ × 30 = ___ /月

对照日注入量: ___ /天
占比: ___%
结论: ✅ 合理 / ⚠️ 偏高 / 🔴 严重膨胀
```

**判定标准：**

| 日总量占日注入比 | 判定 |
|:-----------:|:----|
| < 5% | 可忽略 |
| 5~20% | 合理范围 |
| 20~50% | 需关注，确认有对应回收 |
| > 50% | 🔴 严重膨胀风险 |

### 6.2 相邻插件交叉验证

> 检查一个数值变动后，周边插件是否显得不合理。

**交叉验证步骤：**

1. **列出同货币的所有消费/产出点**（搜索所有插件配置）
2. **按价格排序**，检查相对合理性
3. **检查任务奖励是否仍有吸引力**（商店价格不应碾压任务奖励）
4. **检查回收渠道是否仍然有效**（如果提价，回收是否够用）

**示例：**

```
如果珍材商店"经验修补"从 280 → 300 星痕石：
  → 检查祛魔至宝（8星痕石）是否仍然合理 ✅
  → 检查月卡日产出是否仍然够用（100~150/天 → 300占2天收入）✅
  → 检查任务上交委托的星痕石奖励是否仍有吸引力 ✅
```

### 6.3 公式/配置项逐项核对

> 防止"看起来对但配置写错"的问题。

**核对清单：**

| 检查项 | 方法 |
|:-----|:----|
| YAML 缩进 | 读源文件确认层级正确 |
| 数据类型 | amount 是字符串还是数字？插件要求哪种？ |
| 货币插件名 | `economy-plugin: Vault` 还是 `economy-plugin: vault`？大小写敏感 |
| 限量字段 | `buy-limits` vs `sell-limits`，别搞反 |
| 重置时间 | `TIMED` + `00:00:00` 是否正确组合 |
| 命令引用 | `ferp add xxx -{amount}` 的负号是否在 |
| 权限节点 | `group.vip` 是否与权限插件实际节点一致 |

## 八、定价方法论

> 本节是"从零给一个新物品/新功能定价"的完整方法论。
> 当你不知道一个东西该卖多少时，按以下步骤推导。

### 8.1 定价五步法

```
步骤 1：确定货币种类
    └→ 日常消耗？→ 灵叶
    └→ 高级/稀缺？→ 星痕石
    └→ 建筑材料？→ 块币

步骤 2：确定肝度
    └→ 登录即得？→ ★
    └→ 随手可做？→ ★★
    └→ 专门花时间？→ ★★★
    └→ 高难度？→ ★★★★
    └→ 几乎不可重复？→ ★★★★★

步骤 3：查定价区间表
    └→ 根据 4.2 节，肝度★对应日收入1~5%区间
    └→ 取区间中位值作为初始价格

步骤 4：防套利验证
    └→ 能否从其他渠道低价买入再卖？
    └→ 任务上交奖励是否低于卖商店？
    └→ 交叉检查所有相关价格链

步骤 5：限量评估
    └→ 该资源可再生？→ 需要限量
    └→ 不可再生？→ 不需要限量，供应池自然调节
```

### 8.2 供应池模式定价法

> 适用于稀有资源交易所这类"玩家卖入→进池→玩家买入→出池"的商店。

**定价公式：**

```
卖价（玩家得） = 基准锚 × 肝度系数
买价（玩家付） = 卖价 × (1 + 差价率)
差价 = 买价 - 卖价  → 这部分被系统回收
```

**参数表：**

| 参数 | 取值 | 说明 |
|:----|:----|:----|
| 基准锚 | 1,200 灵叶/钻石 | 全服最硬锚点 |
| 肝度系数 | 0.3~1.0 | ★★★~★★★★★ 对应 |
| 差价率 | 25~33% | 官方回收率 |

**实例：远古残骸定价**

```
肝度: ★★★★（下界挖矿，需要钻石镐）
基准锚: 1,200（钻石卖价）
远古残骸 vs 钻石 = 2.5x 稀有度（更难挖）
卖价 = 1,200 × 2.5 = 3,000 ✅
买价 = 3,000 × 1.33 = 4,000 ✅
差价 = 1,000（33%回收率）✅
```

### 8.3 任务委托定价法

> 适用于"上交物品换奖励"的任务，本质是变相回收。

**定价公式：**

```
灵叶奖励 ≤ 卖商店价格（防止套利）
星痕石奖励 = 额外吸引力（补偿灵叶低于卖价的损失）
总价值 ≈ 卖商店价 × 0.6~0.8（让玩家觉得"亏灵叶但赚星痕石"）
```

**实例：每日宝石商会任务**

```
上交: 8 颗钻石
卖商店可得: 8 × 1,200 = 9,600 灵叶
任务奖励: 3,000 灵叶 + 15 星痕石 + 15min 飞行
  灵叶占比: 3,000/9,600 = 31%（远低于卖价，防套利 ✅）
  星痕石价值: 15 × 45 = 675 灵叶等价
  飞行价值: 15min ≈ 500 灵叶
  总价值: 3,000 + 675 + 500 = 4,175 ≈ 卖价的 43%
  结论: ✅ 玩家缺星痕石才交任务，缺灵叶则卖商店
```

### 8.4 珍材商店定价法

> 适用于用星痕石购买的特殊物品商店。

**定价公式：**

```
价格（星痕石） = 肝度 × 日收入占比目标 / 日收入
             = 肝度系数 × 目标占比 × 100~150
```

**肝度系数表：**

| 肝度 | 系数 | 目标占日收入 |
|:----|:---:|:--------:|
| ★★ | 0.3 | 10~20% |
| ★★★ | 0.5 | 20~40% |
| ★★★★ | 1.0 | 40~80% |
| ★★★★★ | 1.5~2.5 | 80~200% |

**实例：经验修补附魔书**

```
肝度: ★★★★（稀有附魔，需大量钓鱼/交易）
系数: 1.0
目标占比: 200%（2天收入）
价格 = 1.0 × 200% × 150 = 300 星痕石 ✅
```

### 8.5 龙蛋委托定价法（特殊案例）

> 龙蛋可循环获取（每条龙掉一颗），能打龙的玩家可能垄断。

**设计要点：**

1. 不走官方商店买卖（无法定价"无限可再生品"）
2. 走任务委托 + 全服限量
3. 奖励锚定"打龙一次的时间成本"≈ 1 天收入

```
龙蛋委托: 20,000 灵叶 + 50 星痕石
  灵叶: 20,000 ≈ 1天收入（打龙约需半天~1天）
  星痕石: 50 ≈ 半天收入
  全服日限: 2 颗（防垄断）
  结论: ✅ 不会无限印钞，也不鼓励垄断
```

### 8.6 死循环预防设计法

> 设计任何阶梯/条件解锁机制前，必须检查解锁链。

**检查方法：**

```
1. 列出所有解锁条件: A 需要 X, X 需要 Y, Y 需要 Z
2. 反向追溯: Z 的获取是否依赖 A？
3. 如果是 → 死循环 🔴
4. 解决方案: 在链条中插入一个不依赖该系统的入口
```

**通用安全模式：**

```
入口: 不需要任何权限的基礎活动（钓鱼/挖矿/杀怪）
  → 积累基礎货币
  → 购买/解锁第一级权限
  → 该权限提供新的获取渠道
  → 积累更多货币
  → 解锁下一级
```

**关键原则：** 链条的入口必须是"人人都能做的基礎活动"，不能依赖任何上级解锁。

## 十、维护说明

### 10.1 更新时机

以下情况需更新本工作流文档：

1. **经济系统重大调整**（新货币、汇率变动、日收入基准变化）
2. **新增/移除经济插件**（新的产出源或消耗端）
3. **审查中发现新问题类型**（检查清单需新增项）
4. **季度性全服经济体检后**（基准数据校准）

### 10.2 更新流程

```
1. 更新「基准知识库」（第一章）中的数值
2. 更新「全插件经济速查表」（第九章）中的数值
3. 如有新问题类型 → 新增检查清单项
4. 如有新定价模式 → 新增定价方法论章节
5. 同步更新配套文档：
   - /play/systems/economy（玩家版）
   - /developer/reference/economy（基准版）
6. 提交 Git，标注变更原因
```

### 10.3 Agent 使用指引

> AI Agent 接到经济相关任务时，按以下流程使用本文档：

```
1. skill_view(name='miragedge-development') 加载开发技能
2. 读取本文档（/developer/reference/economy-audit-workflow）
3. 执行阶段一~五的完整审查流程
4. 按报告模板输出审查结果
5. 如有修改 → 修改后重新跑阶段二~三验证
6. 将审查结果同步到 session 记录
```
