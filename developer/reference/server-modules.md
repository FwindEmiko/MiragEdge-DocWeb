# 服务器模块职责

本页面面向服主和开发者，用于确认服务器内部模块的职责边界、配置核对入口和维护注意事项。玩家操作说明仍在[特色功能](/plugins/)；可独立部署的原创插件则集中在[原创插件文档](/plugin-guides/)。

## 事实边界

当前服务器配置索引的快照日期为 **2026-07-26**。配置文件能证明“服务器当前写了什么”，不能单独证明所有运行时行为；涉及命令、权限、跨服和 Java/基岩版差异时，仍需结合 JAR、启动日志和游戏内验收。

不要把数据库地址、代理密钥、账号信息或其他敏感字段复制到公开文档。服务端内容索引只用于核对功能，不是公开配置备份。

## 自定义物理与反作弊桥接层

服务器中的道具、技能或数据包效果可能会合法改变移速、鞘翅滑翔速度或实体碰撞箱。这类效果不能靠关闭反作弊检测来兼容：关闭 Matrix 或 Vulcan 的 Move、Elytra、Phase、HitBox 整类检查，会同时放开 Speed、ElytraFlight、穿墙和 Reach 等无关作弊。

桥接层的职责是让**产生合法效果的插件**短暂记录并证明本次物理变化，再只忽略与该状态严格匹配的一次低层违规。它不是反作弊替代品，也不是给玩家发放常驻豁免。

### 配置与插件的职责边界

Matrix 与 Vulcan 的配置只用于保守容错：提高处罚 VL、加快 VL 衰减，或把纯速度、碰撞类的部分子检查降为管理员观察。YAML 无法识别“这次超速究竟来自哪一件合法道具”，因此不能仅靠配置彻底区分道具效果和外挂。

精确兼容由产生效果的插件负责。插件在服务端确认效果已经实际生效后，维护合法物理状态；反作弊报告违规时，再按检查类型决定是否忽略这一次低层违规。LiteBans 等处罚链仍按反作弊的其余结论执行。

### 禁止的兼容方式

- 不关闭 Move、Elytra、Phase、HitBox 的整个检测类别来兼容道具。
- 不通过 LuckPerms 或其他方式给玩家、用户组发放常驻或短时的全局 Matrix/Vulcan bypass。
- 不仅因玩家手持某件物品就豁免；必须由服务端确认该物品或技能的效果已经实际生效。
- 不把 Phase 作为常规道具豁免项。合法碰撞重叠只能精确放行插件已验证的那一次位移，不能让持有碰撞箱道具的玩家持续免检。

### 合法物理状态

推荐以玩家 UUID 为键维护内存状态，或采用具备同等生命周期和可信边界的实现。每条状态至少包含以下字段：

| 字段 | 用途 |
| --- | --- |
| 效果类型 | `MOVE`、`ELYTRA`、`HITBOX`；只有必要时才使用一次性 `PHASE`。 |
| 来源 | 已确认的道具 ID 或技能 ID，便于审计和追踪异常来源。 |
| 生命周期 | 开始时间、过期时间；可选记录最高合法速度或合法尺寸。 |
| 一次性标识 | 对 `PHASE` 记录一次位移 token 或 tick 标识，禁止重复使用。 |

效果开始时创建或刷新状态。状态最长 1 秒自动失效；持续效果必须每个 tick 或短周期续期。效果结束、主动取消、死亡、切换世界、传送、下线和插件禁用时必须立即清理。

状态不可序列化为可由客户端伪造的数据。PDC、Lore、客户端数据包或权限本身都不能作为唯一可信判据；它们最多只能帮助插件找到候选来源，实际效果仍须由服务端状态确认。

### 违规事件的匹配规则

订阅当前实际安装版本的 Matrix/Vulcan 违规事件；具体 API 类名、检查名称和取消方式必须以当前 JAR 或 API 文档为准。桥接层只允许按“状态效果类型 + 反作弊检查类型”的白名单匹配，取消或忽略对应的低层违规；其余违规一律交回反作弊处理。

| 合法状态 | 允许短时桥接的范围 | 绝不能覆盖的范围 |
| --- | --- | --- |
| `MOVE` | 移动速度相关的低层 flag | 飞行、Timer、BadPackets、NoFall、Phase。 |
| `ELYTRA` | 鞘翅或滑翔速度相关的低层 flag | 无鞘翅飞行、Timer、穿墙。 |
| `HITBOX` | 已知的碰撞、角度或距离误差 | KillAura、Aim、AutoClicker；超距离攻击仍须审计。 |
| 一次性 `PHASE` | 插件主动执行、目标已验证安全且时限极短的一次位移 | 持续或重复 flag、跨 tick、跨世界的 flag，以及任何常态穿墙。 |

### 日志、并发与异常处理

每次桥接都记录：被忽略的检查、原因、道具或技能 ID、状态时长、玩家、世界、坐标、ping 和 TPS。日志仅供管理员排障，不向玩家公开反作弊实现细节。

遵循 Bukkit/Paper 的主线程约束：不得在异步线程直接修改玩家状态，或取消同步违规事件。对单个玩家设置状态数量上限和刷新频率限制；插件禁用时清空全部状态。

来源异常、超出设计上限、状态与实际装备或技能不一致时，均不豁免并写入管理员日志。该机制只忽略特定、已验证的合法 flag，不能取代反作弊处罚和反作弊配置。

### 验收矩阵

| 场景 | 可以桥接 | 必须继续检测与处罚 |
| --- | --- | --- |
| 合法移速道具 | 短时 Move 低层速度 flag | 飞行、Timer。 |
| 合法鞘翅加速 | 短时 Elytra 速度低层 flag | 无鞘翅飞行、穿墙。 |
| 合法碰撞箱变化 | 已知 HitBox 低层误差 | KillAura、Aim、AutoClicker。 |
| 受控一次性位移 | 仅该 tick 的 Phase 低层 flag | 连续穿墙、跨 tick 或跨世界位移。 |
| Speed、ElytraFlight、Timer、飞行、持续穿墙、Reach | 不桥接 | 必须继续进入 Matrix/Vulcan 的告警、回退、踢出或 LiteBans 阶梯处罚。 |

静态构建只能验证文档，不会证明事件桥接已经在真实服务器上生效。每种道具、技能和一次性位移都必须在服内完成合法路径、异常路径、重连、传送、死亡和插件重载验收。

## 维护顺序

1. 先确认当前服务端内容索引和插件是否仍处于活跃状态。
2. 再确认配置字段、命令和权限是否来自当前版本，而不是旧项目文档。
3. 改动后分别检查 Java 菜单、基岩版表单、跨插件联动和重启后的数据持久化。
4. 只有完成运行时验收，才把行为写入玩家页面；无法确认的内容留在[开发归档](/developer/archive/plugins/)。
