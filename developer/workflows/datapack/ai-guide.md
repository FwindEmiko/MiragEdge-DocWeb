# 数据包工作流 · AI 指南

这页说明 AI 处理数据包与 CraftEngine 请求时的能力边界与输出规范。

## 能力边界

| 能力 | 覆盖 | 不覆盖 |
| --- | --- | --- |
| 数据包项目搭建 | 完整结构 | — |
| mcfunction 编写 | 通用逻辑、CE 物品检测 | 复杂红石与命令方块逻辑 |
| 原版配方 | 所有类型 | — |
| CE 配方 | 基础、烧炼、附魔结果 | 高级 post-processor、自定义 event |
| 战利品表 | 方块、生物、箱子 | 高级谓词条件组合 |
| CE 物品 | 属性、附魔、食物、装备 | 高级 behavior、家具、client-bound-data |
| CE 方块 | 基础方块、战利品表 | 多状态复杂方块、方块 behavior |
| 结构 | 单模板结构 | 拼图结构的大型拼接 |
| 世界生成 | CE 方块 provider | 复杂的自定义维度与噪声 |

## 执行流程

```text
第 1 步：阅读前置条件
  → 确认命名空间、版本、环境约束

第 2 步：匹配功能模块
  → 定位函数、战利品表、配方、生物掉落、CE 物品、结构中的一类

第 3 步：按五步闭环执行
  → 概念理解 → 设计方案 → 编写代码 → 验证命令 → 部署说明

第 4 步：交付输出
  → 提供可直接复制的代码文件
  → 附带验证命令
  → 标注需要手动操作的步骤
```

## 命名与路径规范

- 命名空间固定为 `miragedge`。
- `pack_format` 使用 `101`，对应 MC 26.1.2，以实际环境为准。
- 文件路径使用 `data/miragedge/<type>/<path>.json` 格式。
- CE 物品 ID 使用 `miragedge:<snake_case_name>`。
- 函数路径使用 `miragedge:<category>/<function_name>`。
- 命令中的 ID 一律写完整命名空间，不省略 `miragedge:`。

## 交付输出

输出格式的通用要求见[通用交付标准](../_shared/ai-delivery)。数据包场景下还需额外满足：

- 区分 CE YAML 与数据包 JSON，明确标注本次改动落在哪一侧。
- CE 物品作为原料或产物时，配方一律写在 CE YAML 中。
- 涉及世界生成的改动必须注明需要重启服务器，而不是只执行 `/reload`。
