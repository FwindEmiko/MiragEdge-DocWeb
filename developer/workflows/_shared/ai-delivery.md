# AI 交付规范

这页规定 AI 交付开发产物时的输出格式。适用于数据包、钓鱼系统及其他工作流。

## 五项硬要求

1. **可操作**：每个代码块可直接复制使用。
2. **完整**：包含文件路径注释，如 `// data/miragedge/loot_table/blocks/ruby_ore.json` 或 `# rods/my_rod.yml`。
3. **可验证**：每个模块附带验证命令。
4. **有上下文**：说明文件之间的依赖关系与生效顺序。
5. **标注版本差异**：明确区分原版数据包 JSON 还是插件 YAML，并标出会因版本变化的字段。

## 占位符规则

占位符必须用尖括号包裹并集中说明，不要散落在代码中。

```text
<namespace>      命名空间，本项目为 miragedge
<player>         测试玩家名
<release-id>     发布批次编号
```

## 未覆盖内容的处理

遇到现有文档未覆盖的问题时，按以下顺序处理：

1. 查官方文档与 Wiki。
2. 查原版数据包，路径为 `<server.jar>/data/minecraft/`。
3. 用 Misode 等生成器确认 JSON 格式。
4. 检视服内实际配置文件。
5. 增量验证，每完成一项立即测试，不要全部写完再验证。
6. 对确实无法确认的功能，明确说明不确定，不要编造字段或数值。

## 交付清单

每次交付必须同时给出：

- 改动文件清单与绝对路径。
- 每个文件的职责一句话说明。
- 生效命令与预期结果。
- 未能验证的事实清单，注明冲突来源与处理方式。
